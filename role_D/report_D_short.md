## 5. Controlled layout experiment (Role D)

Layout experiment (Silver v1 -> 971,000 synthetic rows = 9,710 x 100 replicas). Both layouts returned identical results (4 sites, 2,500 observations each). Query times (s), order A-B, B-A, A-B: A = 0.582, 0.527, 0.514; B = 0.456, 0.402, 0.350. Median A = 0.527 s, median B = 0.402 s, median(A)/median(B) = 1.31. Layout B was faster in every round, but with three samples per layout on local[2] and a ~16 MB table, the difference (~0.1 s) is small and both layouts also speed up over rounds, so these are warm repeated runs, not cold-cache results. The plan for B shows PartitionFilters: event_date = 2026-02-06 and omits event_date from ReadSchema; the plan for A only shows a pushed filter plus a row-level Filter. Total table files (A = 32, B = 5) are table metadata, not files scanned; actual scan metrics must come from the Spark UI. Setup time (A = 13.9 s, B = 6.2 s) is excluded from query times. Replicas are synthetic copies, not independent observations, and were never written to operational Gold.
